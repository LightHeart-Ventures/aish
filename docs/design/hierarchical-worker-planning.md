# Hierarchical worker planning for aish

**Status:** design proposal (no code in this PR).
**Source material:** `LightHeart-Ventures/dai` PRs #129, #130, #134, #136, #139 —
the hierarchical agent planner that is now dai's **runtime default**.
**Relationship to existing aish work:** [`docs/workers-hierarchy.md`](../workers-hierarchy.md)
made the worker *tree* visible and durable (`AISH_RUN_ID` / `AISH_PARENT_RUN_ID`,
`coordinator_runs.parent_run_id`, forest rendering in `:workers`). That is the
*plumbing*. This document is the *planning layer* that decides **who gets spawned,
what each one is allowed to produce, and how the results are merged**.

## 1. What dai shipped

| PR | Title | Nature |
| --- | --- | --- |
| #129 | docs: propose hierarchical agent subdomain split (design only) | Design: supervisor/team/worker split, bounded subdomains, separate effect authorities (`docs/design/hierarchical-agent-subdomains.md`) |
| #130 | Design: hierarchical agent coordination protocol | Design: task/report coordination, delegation criteria, nested budgets, recovery outcomes, metadata-only progress (`docs/design/hierarchical-agent-protocol.md`) |
| #134 | Hierarchical planner: root supervisor fans out to 6 concurrent team supervisors over disjoint scene keys | Implementation, +1172 LoC, 12 tests, **default-on, no opt-in flag** (`hierarchy.py`) |
| #136 | docs: architect-utterance capability gap analysis | Evidence: 300 operator utterances replayed against the new planner to find uncovered capability |
| #139 | Fix hierarchical proposal routing and oversized team responses | Production fix: effect-family routing backstop, per-role token budgets, router moved to a cheap tier, fixed telemetry spans (`docs/designs/hierarchy-effect-routing.md`) |

### The mechanism (`hierarchy.py`, ~317 lines)

```
user event
   │
   ▼
root supervisor  (cheap "interact" tier, 600-token output cap)
   │  decides: which OPTIONAL teams run (max 4) + writes ONE shared brief (<=600 chars)
   │  never builds anything itself
   ▼
fan-out: ThreadPoolExecutor(max_workers=len(teams)), contextvars.copy_context() per worker
   │
   ├── conversation  (MANDATORY)  owns reply, needs_input, options, selection      2k tokens, streams
   ├── surface       (MANDATORY)  owns title, body, widgets, theme, layout…        8k tokens
   ├── parts         (optional)   owns component_definitions, widget_definitions   8k tokens
   ├── data          (optional)   owns storage_definitions, bindings…              8k tokens
   ├── applications  (optional)   owns application_draft, catalog_proposal…        8k tokens
   └── evidence      (optional)   owns observe_workspace, event_cache, todo        8k tokens
   │
   ▼
arrival filter: `kept = {k: v for k, v in fragment.items() if k in team.keys}`
   │  out-of-scope keys are DROPPED and logged ("dropped out-of-scope keys: [...]")
   ▼
deterministic merge in registry order (key sets are disjoint by construction → no write conflict)
   │
   ▼
single validator: `agent.normalize(merged)`
```

Degradation ladder (every rung is in the shipped code):

| Failure | Behaviour |
| --- | --- |
| Root supervisor errors | log, emit `root/failed`, fall back to **monolithic** planning |
| Optional team errors | log, emit `<team>/failed`, continue with the rest |
| Mandatory team errors | fall back to **monolithic** planning |
| Merged artifact rejected by the validator | emit `merge/degraded`, re-normalize **mandatory teams only** |
| Progress sink raises | swallowed — "a broken sink must not fail planning" |

Operator overrides: `DAI_HIER_ROOT` (router tier), `DAI_HIER_TEAMS` (force the team set,
bypassing the router entirely).

PR #139's hard-won lessons are the most valuable part for us:

1. A "produce the whole artifact" contract **contradicts** per-role fragment charters —
   one of them silently wins and the other's work is discarded.
2. A scene key with **no owning team** is generated by nobody, or generated by the wrong
   team and then dropped by the disjoint merge — so dai added a **source-derived coverage
   test**: every normalized key must map to exactly one team.
3. An explicit user request for an effect family must be **deterministically routed**
   (regex backstop) even when the LLM router forgets it — routing generation is *not*
   authorization, so the backstop is safe.
4. The router is a *small* decision: give it the cheap tier and a tiny output budget
   (measured 1.31 s vs ~71 s for the old reasoning-tier pre-fan-out step).
5. Oversized responses (`finish_reason == "length"`) must raise, not silently truncate.
6. Don't claim a latency win without post-deploy measurement.

## 2. aish today — the gap

| Dimension | dai (after #134/#139) | aish today |
| --- | --- | --- |
| Decomposition decision | explicit router call, cheap tier, bounded output, logged | implicit: the coordinator decides inline, on the expensive model, holding full context |
| Role definition | fixed registry in source (`TEAMS`), charter + owned keys + tier + budget | free-text `task` string per `run_in_background` call; no declared role |
| Output ownership | disjoint key sets, enforced at arrival | none — two workers may touch the same file; discovered later as a conflict |
| Shared intent | one `brief`, written once, given to every team | re-described per worker, in prose, inconsistently |
| Context thrift | per-team `wants_context` / `catalogs` flags | each worker re-discovers the repo from scratch |
| Merge | deterministic order + one validator | human/steward reads prose results; `lightheart/merge-steward` skill patches over it |
| Degradation | 5-rung ladder, codified | loop guards, stand-down, turn/call budgets — but no mandatory/optional semantics and no "fall back to monolithic" rule |
| Coverage guarantee | source-derived test: no unowned key | none — a repo area can be owned by every worker or none |
| Telemetry | fixed span allowlist `agent.hierarchy.{plan,root,<team>}`, no prompt/credential attributes | per-run rows + transcripts; no per-role spans |

aish already has the *expensive* half of hierarchy (durable runs, worktree isolation,
spawn broker + policy, `tell`/`stop` steering, parentage, batch tier). What it lacks is
the **declared contract** that makes concurrent fan-out safe and cheap.

## 3. Design: role registry → router → scoped fan-out → validated integration

### 3.1 Role registry (`src/worker_roles.rs`)

```rust
pub struct Role {
    pub name: &'static str,       // stable id, used in prompts, spans, overrides
    pub owns: Vec<String>,        // path globs this role may modify (disjoint across roles)
    pub tier: Tier,               // Interactive | Batch (existing fan-out tiers)
    pub mandatory: bool,          // always runs for this program
    pub wants_repo_context: bool, // inject repospec/architecture block?
    pub turn_budget: u32,         // existing per-run turn/call budget, per role
    pub charter: &'static str,    // "You own X. Do not touch Y. Produce Z."
}
```

Roles are grouped into **programs** (dai has exactly one program — "render a turn");
aish needs a couple:

**Program `code-change`** (default for a feature/fix fan-out):

| Role | Owns (globs) | Mandatory | Tier |
| --- | --- | --- | --- |
| `impl` | the module(s) named by the router, from `.repospec.json` `modules` | yes | interactive |
| `tests` | `tests/**`, `**/*_test.rs`, `**/test_*.py` | yes | interactive |
| `docs` | `docs/**`, `README.md`, `release_notes/**` | no | batch |
| `ci` | `.github/**`, `Makefile`, `justfile` | no | batch |
| `data` | `migrations/**`, `schema/**`, `**/*.sql` | no | interactive |
| `review` | **nothing** (read-only; emits findings, no diff) | no | batch |

**Program `analysis`** (read-only investigations): every role owns nothing; outputs are
report sections with disjoint headings — the dai key-ownership model applied to a document.

Ownership is **repo-derived, not invented**: globs resolve against `.repospec.json`
(`modules`, `key_files`) so the registry and the repo cannot drift silently.

### 3.2 Router turn

A single cheap-model call before fan-out:

- system prompt: the role menu (`name: purpose` lines) + "you do not build anything";
- output: `{"roles": ["docs","data"], "brief": "one or two sentences"}`, **600-token cap**,
  mandatory roles implied, **max 4 optional**;
- `AISH_HIER_ROUTER=<tier>` overrides the router model; `AISH_HIER_ROLES="impl,tests,docs"`
  bypasses the router (dai's `DAI_HIER_TEAMS` analogue — the operator escape hatch);
- **deterministic backstop** (dai #139): if the task text matches an effect family whose
  role the router omitted, append it. Initial table: `migration|schema|\.sql` → `data`;
  `CI|workflow|actions` → `ci`; `README|docs/` → `docs`. Routing generation only — it
  grants no new permission, and never promotes a reversible action to an irreversible one.
- the router's chosen set and brief are **logged and shown** (`message_console`), because
  a wrong decomposition must be visible *before* six workers burn an hour.

### 3.3 Shared brief

One ≤600-char brief, written once by the router, pinned verbatim into every worker's task
block (aish already pins the verbatim task — the brief rides alongside it). It replaces the
per-worker re-description that currently drifts between siblings.

### 3.4 Scoped worker contract

Each selected role spawns one worker with:

- the **verbatim operator task** (unchanged — still the single source of truth),
- the shared brief,
- its charter plus an explicit ownership clause:
  > You own exactly these paths: `<globs>`. Other roles are working the rest of this task
  > concurrently. Changes you make outside your paths are **reverted on arrival** and
  > wasted — if you believe a foreign path must change, say so in your result instead.
- repo-context block only when `wants_repo_context` (token thrift — dai's `wants_context`),
- its own isolated worktree branched from **one shared base SHA** (existing `isolate:true`,
  `base:"main"`), so disjoint diffs compose without a merge at all,
- its own tier + turn budget from the registry.

### 3.5 Arrival filter (the load-bearing invariant)

dai drops out-of-scope *keys*; aish drops out-of-scope *paths*. In the parent, per child
branch:

```
git diff --name-only <base>..<child-head>
  → owned   = paths matching role.owns     → kept
  → foreign = everything else              → reverted (git checkout <base> -- <path>)
                                             and reported in the run result
```

The filter runs in the **parent**, not the child: the worker is not trusted to self-police,
exactly as dai's merger — not the team — enforces key scope. Every reverted path is logged
(dai's `dropped out-of-scope keys` line) and surfaced in the fan-out summary, because a
pattern of reverts means the registry's ownership map is wrong.

### 3.6 Deterministic integration + one gate

1. Create `integration/<fanout-id>` from the shared base SHA.
2. Apply role branches **in registry order** (stable, like dai's `for name in names:
   merged.update(...)`). Disjoint paths ⇒ no conflict by construction; a conflict is a
   *bug in the ownership map*, and is reported as one rather than hand-resolved.
3. **Single validator** — the `agent.normalize` analogue — is one build+lint+test run on
   the integrated tree (plus the existing `lightheart/merge-steward` semantic-conflict
   check for the set).
4. One **draft** PR per fan-out, not per worker. Merging stays with the operator:
   irreversible actions never move to the agent side of the line.

### 3.7 Degradation ladder (ported rung for rung)

| Failure | aish behaviour |
| --- | --- |
| Router fails / returns junk | log + console note, spawn **one** monolithic worker (today's behaviour) |
| Optional role fails | integrate the rest; name the gap in the PR body and the final report |
| Mandatory role fails | abandon the fan-out, fall back to one monolithic worker on the same base |
| Integration gate fails | keep mandatory roles only, re-run the gate; still red → draft PR + explicit failure report, **never** auto-merge |
| Progress/console sink fails | swallowed; a reporting failure must not kill a fan-out |

### 3.8 Progress and telemetry

- Per-role status transitions (`spawned → running → done/failed`) written to
  `coordinator_runs` (the tree from `docs/workers-hierarchy.md` renders them) and
  summarized once to the operator console.
- Fixed span allowlist: `aish.hier.plan`, `aish.hier.router`, `aish.hier.role.<name>`,
  `aish.hier.integrate`. **Metadata only** — no prompt text, no task text, no credentials
  (dai #139 added exactly this allowlist with the same restriction).
- Measured per role: wall-clock, turns, tool calls, tokens, reverted-path count.

### 3.9 Structural coverage test

dai's most durable guard is a *source-derived* test that no scene key is unowned. aish's
equivalent, as a plain unit test:

1. role globs are **pairwise disjoint** within a program;
2. every `modules` / `key_files` entry in `.repospec.json` is owned by **at least one**
   role in `code-change`;
3. every role is reachable from the router menu (no orphan roles);
4. the effect-family backstop table references only roles that exist.

This is the test that stops the registry rotting as the repo grows.

## 4. Phasing

| Phase | Deliverable | Acceptance |
| --- | --- | --- |
| P0 | `worker_roles.rs` registry + coverage test. No behaviour change. | `cargo test --no-default-features --locked` green; disjointness + repospec coverage asserted |
| P1 | Router in **shadow mode** behind `AISH_HIER=shadow`: compute roles + brief, log them, then run today's monolithic path. | For 20 real fan-outs, recorded router decisions reviewed for sanity; router p50 latency and cost recorded |
| P2 | Scoped fan-out + arrival filter behind `AISH_HIER=on`. | A real multi-role task produces N branches with zero foreign paths after filtering; reverted paths reported |
| P3 | Integration branch + single gate + one draft PR per fan-out. | Integrated tree builds and tests green; conflict ⇒ reported as ownership-map bug, not hand-fixed |
| P4 | Telemetry spans, `:workers` role column, docs, default-on for `code-change`. | Before/after numbers published (§6); operator override documented |

Each phase is one PR, mirroring dai's own sequence (design → implementation → evidence → fix).

## 5. What NOT to port

- **Default-on from day one.** dai's unit of work is one user turn (seconds, no side
  effects). An aish fan-out spends minutes to hours and *writes to a repo*. Shadow mode
  first, default-on last, and never auto-merge.
- **Hard 8k output caps.** aish workers legitimately produce long diffs; the right bound is
  the existing **turn/tool-call budget**, not an output-token guillotine. Keep the small cap
  where dai put it — on the **router**.
- **Thread fan-out.** dai uses `ThreadPoolExecutor` + `contextvars`; aish already has
  stronger isolation (processes + git worktrees). The analogue of `copy_context()` is the
  pinned verbatim task + brief + base SHA stamped into each child's env.
- **Streaming one special role.** dai streams only `conversation`; aish's equivalent is
  console notes from the parent, not child stdout relaying (that's the open follow-up in
  `docs/workers-hierarchy.md` §4).

## 6. Risks and measurement

| Risk | Mitigation |
| --- | --- |
| Ownership map drifts from the repo | §3.9 coverage test wired into CI; globs resolved from `.repospec.json` |
| Router picks the wrong roles | shadow mode, console visibility, effect-family backstop, `AISH_HIER_ROLES` override |
| Fan-out cost balloons (6 workers per task) | router caps optional roles at 4; `review`/`docs`/`ci` default to the cheap batch tier |
| Partial integration ships half a feature | mandatory roles; gate must be green; draft PR + explicit gap list |
| "It's faster now" without evidence | §6 numbers, per dai #139's explicit refusal to claim a latency win pre-measurement |

**Measure before claiming anything**, on the same workload before and after:
wall-clock per merged PR, tokens and dollars per merged PR, merge conflicts per fan-out,
re-work turns after integration, reverted foreign paths per role, and router latency/cost
as a share of the whole run.

## 7. Open questions

1. Where does the registry live — compiled-in defaults only, or overridable per repo via
   `.aish/roles.toml` (with the coverage test run against the override)?
2. Should `review` be a role inside the fan-out or stay a post-integration step
   (`lightheart/ci-triage` / `ac-audit` already occupy that ground)?
3. Does the router run in the parent coordinator's context, or as its own cheap one-shot
   process (cleaner span boundary, one more spawn)?
4. For `analysis` programs, is "disjoint report headings" enough, or do we need dai's
   stricter key-level contract for structured outputs?
