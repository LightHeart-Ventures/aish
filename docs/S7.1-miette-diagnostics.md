# S7.1 / TASK-139 — PRD: miette-backed diagnostics (spans + codes + hints)

> Durable repo copy of the S7.1 PRD. Source of record: Atum card TASK-139
> (`card_8aa65edb8b5a`), `productSpec` field. Keep this file and the card in sync.

## Problem
aish has no first-class error type. Parse/routing failures return `Option::None` and the line silently routes to the model; config errors are dropped with ad-hoc dim `eprintln!`s (no location/code); exec failures are flat `anyhow` strings. A mistyped quote is indistinguishable from genuine intent, and a bad `~/.aishrc` line gives no column or fix.

## Goal
Adopt **miette** (MIT — a dependency, not clean-room; the engine behind nushell's diagnostics) to give aish its own diagnostic surface: byte-span carets, stable codes, and did-you-mean help across parse / config / exec errors — without changing routing semantics.

## Acceptance criterion (card AC)
> a routing/parse error renders with a caret + code + hint

## Design (see doc §4)
- New `src/diag.rs` with one `AishDiagnostic` enum deriving `miette::Diagnostic` (+ thiserror): `#[source_code]` source string, `#[label]` `SourceSpan` caret, `#[diagnostic(code(...))]`, `#[help]`.
- Codes: `aish::parse::{unbalanced_quote,unsupported_meta,empty_stage,bad_var_ref}`, `aish::config::bad_export`, `aish::exec::not_found`.
- `rc::tokenize_diagnosed` — span-aware sibling of `tokenize`; every existing `return None` becomes a spanned `Err`. `tokenize`/`tokenize_pipeline` stay as `.ok()` shims → **zero behavioural change** for the silent route-to-model path.
- Convert the `rc::parse_into` `eprintln!` skip sites to coded, located `BadConfigLine` diagnostics (header `~/.aishrc:42`); parsing still continues past a bad line.
- Map exec `NotFound` spawn errors to `ExecFailed` with a `$PATH`-aware hint (cheap did-you-mean only).
- One `diag::render` picks miette's unicode vs none theme via the existing `style::colors_enabled()` (NO_COLOR/`--no-color`/non-TTY → plain, still caret+code+help).

## Acceptance criteria (testable — doc §5)
1. Forced-shell parse failure renders caret + `aish::parse::` code + `help:` line (plain theme, TTY-independent).
2. `tokenize`/`tokenize_pipeline` byte-for-byte unchanged; existing tests pass untouched.
3. Each of the six codes stable and unit-tested.
4. Span offsets equal the offending char index (`|` in `a | | b`, `'` in unbalanced quote, `B` in `export A=1 B=2`).
5. Malformed `~/.aishrc` line → coded/located diagnostic AND rc parsing continues.
6. NO_COLOR → no ANSI but still caret+code+help; color on → graphical theme.

## Non-goals
No routing-semantics change (default REPL fallback stays silent); no `$PATH`-wide spell-checker (infra only); no i18n; no wholesale `anyhow`→`miette` migration.

## Plan
