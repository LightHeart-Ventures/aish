# S7.1 / TASK-139 — PRD: miette-backed diagnostics (spans + codes + hints)

> nushell makes a bad command *teachable*: a byte-span caret points at the exact
> offending character, a stable error code names the failure, and a "did you
> mean…" hint offers the fix. aish today fails the same inputs **silently** —
> the tokenizer returns `None` and the line is quietly handed to the model, or a
> config line is dropped with a dim one-liner. This card gives aish its own
> diagnostic surface, built on **miette** (MIT — a dependency, not clean-room),
> so parse / routing / config / tool errors render with a caret, a code, and a
> hint.

- **Card:** S7.1 — `cargo add miette`; wrap parse/tool/config errors with spans + codes
- **Sprint:** S7 · **Priority:** high · **Points:** 5
- **Acceptance criterion:** *a routing/parse error renders with a caret + code + hint*

---

## 1. Problem

aish has no first-class error type and no diagnostic renderer. Failures surface
in three inconsistent, low-signal ways:

| Failure class | Where | Today's behaviour | What the user sees |
|---|---|---|---|
| Parse / routing | `rc::tokenize`, `rc::tokenize_pipeline`, `pipeline::parse` | returns `Option::None`; the line silently routes to the model | nothing — the input vanishes into an LLM turn, even when the real cause is an unbalanced quote or a stray `>` |
| Config | `rc::parse_into` (`~/.aishrc`, profiles) | line skipped with a hand-rolled dim `eprintln!` | `aish: rc: skipped \`…\` — not a plain NAME=value export` (no location, no code, inconsistent format) |
| Tool / exec | `pipeline::exec`, direct dispatch | `anyhow::anyhow!("failed to exec {program}: {e}")` | a flat string, no caret, no remediation |

The result: a mistyped quote (`what's eating my disk`) is indistinguishable from
genuine intent — both route to the model — and a malformed `~/.aishrc` line is
discarded with a message that doesn't say *which column* is wrong or *how to fix
it*. There is no stable code to grep for, document, or test against.

### Why now / why miette

nushell's celebrated diagnostics are powered by **miette**. miette is MIT, so we
**depend on it directly** (this is explicitly *not* a clean-room reimplementation
— see the card description). It gives us, for free, the three things the AC
demands: `#[diagnostic(code(...))]`, `#[label("…")]` byte-span carets via
`SourceSpan`, and `help("…")` hint text — rendered by its `GraphicalReportHandler`
with the same fancy-Unicode look nushell ships, and a NO_COLOR/no-TTY-aware plain
fallback that matches our existing `style::colors_enabled()` policy.

---

## 2. Goals & non-goals

**Goals**
- G1. Introduce one aish error enum, `AishDiagnostic`, deriving `miette::Diagnostic`, that carries a **source string**, a **byte-span label** (caret), a **stable code**, and a **help hint** for every failure it represents.
- G2. Make the tokenizer/pipeline parser able to report *why* a line is not a runnable command (unbalanced quote, unsupported metacharacter, empty pipeline stage, malformed `${…}`) **with the offending byte offset** — without losing today's "route to the model" fallback.
- G3. Replace the three ad-hoc `eprintln!` config-skip messages in `rc::parse_into` with coded diagnostics that point a caret at the bad span of the `~/.aishrc` line.
- G4. Wrap tool/exec failures (`failed to exec …`) in a coded diagnostic with a remediation hint (e.g. command-not-found → "is it on `$PATH`?").
- G5. Render diagnostics through one helper (`diag::render`) that honours `style::colors_enabled()` (NO_COLOR / `--no-color` / non-TTY → plain graphical report).
- G6. Stable, documented error codes (`aish::parse::*`, `aish::config::*`, `aish::exec::*`) that are unit-tested and greppable.

**Non-goals**
- N1. Changing routing **semantics**. A line the tokenizer can't run still goes to the model; this card only adds an *optional, explanatory* diagnostic the caller may choose to surface (e.g. when the user explicitly forced a shell command). The default REPL fallback stays silent so normal intent isn't nagged.
- N2. A "did you mean `<command>`" spell-checker over `$PATH` binaries. The *infrastructure* for did-you-mean hints lands here (miette `help`), but command-name fuzzy-matching is its own card — this card ships did-you-mean only where it's cheap and unambiguous (e.g. `||` → "use a single `|` for a pipe").
- N3. Localizing or i18n-ing messages.
- N4. Reworking `anyhow` usage across the whole binary. We add `miette` alongside `anyhow`; only the four call sites in §4 convert.

## 3. UX — what the user sees

A forced-shell line with an unbalanced quote, rendered by miette's graphical handler:

```
~/proj ❯ grep 'unterminated
  × aish::parse::unbalanced_quote
   ╭────
 1 │ grep 'unterminated
   ·      ┬
   ·      ╰── this ' is never closed
   ╰────
  help: close the quote, or escape it as \' if you meant a literal apostrophe
```

A malformed `~/.aishrc` export, surfaced at startup:

```
  × aish::config::bad_export
   ╭─[ ~/.aishrc:42 ]
42 │ export A=1 B=2
   ·          ┬
   ·          ╰── a second word starts here — an export is one NAME=value
   ╰────
  help: split this into two lines: `export A=1` and `export B=2`
```

A command-not-found exec failure:

```
  × aish::exec::not_found
   ╭────
 1 │ gti status
   · ──┬─
   ·   ╰── no such program
   ╰────
  help: `gti` is not on $PATH — did you mean `git`?
```

Plain mode (`NO_COLOR` / piped) drops the box-drawing and color but keeps the
caret column, the code, and the help line, so the AC ("caret + code + hint")
holds in every render mode.

## 4. Design

### 4.1 New module: `src/diag.rs`

```rust
use miette::{Diagnostic, SourceSpan};
use thiserror::Error;            // miette pairs with thiserror for the Display derive

#[derive(Debug, Error, Diagnostic)]
pub enum AishDiagnostic {
    #[error("unbalanced quote")]
    #[diagnostic(code(aish::parse::unbalanced_quote),
                 help("close the quote, or escape it as \\' for a literal apostrophe"))]
    UnbalancedQuote {
        #[source_code] src: String,
        #[label("this quote is never closed")] at: SourceSpan,
    },

    #[error("unsupported shell syntax")]
    #[diagnostic(code(aish::parse::unsupported_meta),
                 help("aish runs one program at a time; `{meta}` needs a shell — route via `?<intent>` or a pipeline"))]
    UnsupportedMeta {
        meta: char,
        #[source_code] src: String,
        #[label("aish has no shell to interpret this")] at: SourceSpan,
    },

    #[error("empty pipeline stage")]
    #[diagnostic(code(aish::parse::empty_stage),
                 help("every `|` needs a command on both sides"))]
    EmptyStage { #[source_code] src: String, #[label("nothing here")] at: SourceSpan },

    #[error("malformed variable reference")]
    #[diagnostic(code(aish::parse::bad_var_ref),
                 help("use ${{NAME}} with a closing brace and a valid name"))]
    BadVarRef { #[source_code] src: String, #[label("unterminated or invalid")] at: SourceSpan },

    #[error("invalid rc line")]
    #[diagnostic(code(aish::config::bad_export))]  // help filled per-variant at construction
    BadConfigLine { #[source_code] src: String, #[label] at: SourceSpan, #[help] help: String },

    #[error("could not run `{program}`")]
    #[diagnostic(code(aish::exec::not_found))]
    ExecFailed { program: String, #[source_code] src: String, #[label("no such program")] at: SourceSpan, #[help] help: String },
}

/// Render a diagnostic to stderr honouring style::colors_enabled().
pub fn render(d: &AishDiagnostic) { /* GraphicalReportHandler, theme picked by colors_enabled() */ }
```

`thiserror` is added alongside `miette` (the canonical pairing; both MIT/Apache).
`miette` is added with its `fancy` feature for the graphical handler.

### 4.2 Tokenizer: report *why*, keep the `None` fallback

The tokenizer's value is the silent `Option<Vec<String>>` route-to-model
contract — we must not break it. The fix is a **parallel, span-aware entry
point** that the existing `tokenize`/`tokenize_pipeline` delegate to:

```rust
/// Span-aware tokenize. `Ok(words)` on success; `Err(AishDiagnostic)` names the
/// failure with a byte span. The legacy `tokenize` is `diagnose(...).ok()`.
pub fn tokenize_diagnosed(line: &str, lookup: ...) -> Result<Vec<String>, AishDiagnostic> { … }

pub fn tokenize(line: &str) -> Option<Vec<String>> {           // unchanged signature
    tokenize_diagnosed(line, env_lookup).ok()
}
```

Every existing `return None` in `tokenize_with` becomes a `return Err(diag)` in
`tokenize_diagnosed`, carrying the byte offset already known at that point in the
char scan (the loop has `char_indices`-equivalent position). Callers that want
the explanation (forced-shell dispatch, `pipeline::parse`) call the `_diagnosed`
form; callers that want today's behaviour keep calling `tokenize`. **Zero
behavioural change** for the silent path — verified by the existing
`tokenizer_*` tests, which keep passing untouched.

### 4.3 Config: replace the three `eprintln!`s

`rc::parse_into`'s three skip sites (command-substitution export, non-`NAME=value`
export, and — newly — a malformed alias) construct `AishDiagnostic::BadConfigLine`
with the byte span of the offending token and a per-case `help`, then call
`diag::render`. The function gains the file path + line number so the report
header reads `~/.aishrc:42`. Parsing still **continues** past a bad line (a
single typo must not abort rc loading) — the diagnostic is informational, exactly
like today's dim message but coded and located.

### 4.4 Exec: command-not-found hint

`pipeline::exec` and the direct-dispatch spawn map a spawn `io::Error` of kind
`NotFound` to `AishDiagnostic::ExecFailed` with a `$PATH`-aware help line. The
optional did-you-mean (`gti` → `git`) is a cheap edit-distance scan over the
current line's first word against a small built-in of common typos **plus** the
`$PATH` binaries already cached for autosuggest, if available; absent that, the
hint degrades to "is it installed / on `$PATH`?".

### 4.5 Rendering & color policy

One `diag::render` builds a `miette::GraphicalReportHandler` with
`GraphicalTheme::unicode()` when `style::colors_enabled()` is true and
`GraphicalTheme::none()` (ASCII, no color) otherwise — reusing the single
NO_COLOR/`--no-color`/non-TTY decision aish already centralizes in `style.rs`.
No diagnostic text is printed via `println!`/`eprintln!` directly anymore.

## 5. Acceptance criteria (testable)

- **AC-1 (the card's AC).** A routing/parse error renders with **a caret + a code + a hint**: feeding `grep 'unterminated` (or any forced-shell parse failure) through the diagnosed path produces an `AishDiagnostic` whose rendered output contains (a) a `^`/`┬` caret under the offending byte, (b) the string `aish::parse::`, and (c) a `help:` line. Asserted against the plain-theme render so the test is TTY-independent.
- **AC-2.** `tokenize` / `tokenize_pipeline` behaviour is **byte-for-byte unchanged** — every existing `rc.rs` tokenizer/pipeline test passes without edits, and a line that previously routed to the model still returns `None`.
- **AC-3.** Each error code is stable and unit-tested: `unbalanced_quote`, `unsupported_meta`, `empty_stage`, `bad_var_ref`, `config::bad_export`, `exec::not_found`. A test maps each malformed input to its expected code.
- **AC-4.** Span correctness: for a curated set of inputs, the label's `SourceSpan` offset equals the index of the offending character (e.g. the `|` in `a | | b`, the `'` in an unbalanced quote, the `B` in `export A=1 B=2`).
- **AC-5.** A malformed `~/.aishrc` line renders a coded, located diagnostic **and rc parsing continues** (the remaining valid alias/export lines still load).
- **AC-6.** Render honours color policy: with `NO_COLOR` set the output contains **no ANSI escape** but still shows caret + code + help; with color enabled it uses the graphical theme.

## 6. Implementation plan

1. `cargo add miette --features fancy` and `cargo add thiserror`; record both in `THIRD_PARTY_NOTICES.md` (MIT/Apache — compatible with aish's Apache-2.0).
2. Add `src/diag.rs` with `AishDiagnostic` + `render`; wire `mod diag;` in `main.rs`. Pure unit tests for code/help/theme.
3. Add `rc::tokenize_diagnosed` (and a pipeline equivalent), refactor `tokenize_with`'s `None` returns into spanned `Err`s; keep `tokenize`/`tokenize_pipeline` as `.ok()` shims.
4. Convert the three `rc::parse_into` `eprintln!` skip sites to `BadConfigLine` + `render`, threading file path + line number.
5. Map exec `NotFound` spawn errors in `pipeline.rs` (and direct dispatch) to `ExecFailed` with the `$PATH` hint.
6. Surface a diagnostic at the **forced-shell** dispatch site only (so normal intent stays silent — N1).
7. Tests for AC-1..AC-6; update `CHANGELOG.md`.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Diagnostics leak into the silent route-to-model path and nag the user on every English sentence | The `_diagnosed` form is opt-in; the default REPL fallback still calls `tokenize`/`.ok()` and stays silent (N1, AC-2). |
| Byte-span vs char-index drift on multibyte input | `SourceSpan` is byte-based; the tokenizer already iterates chars — record `char_indices` byte offsets, and add a multibyte span test. |
| miette's `fancy` feature pulls a heavier dep tree | Acceptable for the diagnostic value; the graphical handler is the same one nushell ships. Re-check binary-size delta in the release profile. |
| Inconsistent theme vs the rest of aish's output | `render` routes the theme decision through the existing `style::colors_enabled()` so there's one color policy (AC-6). |

## 8. Out of scope (left as seams)

- `$PATH`-wide command spell-checker (this card ships only cheap, unambiguous did-you-mean hints; the fuzzy matcher is a follow-up).
- Converting the rest of the binary's `anyhow` errors to `miette`.
- Structured/JSON diagnostic output for non-interactive consumers.
- Source-span diagnostics for the model/tool-call layer (MCP, coordinator) — this card scopes to shell parse/config/exec.
