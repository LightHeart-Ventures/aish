# Build Order — TASK-285…298 (Coordinator subsystem hardening)

_Generated by coordinator triage. Source of truth: the 14 cards on SPR-058 (`col_develop`) + live code grounding in `src/coordinator.rs`, `src/worker.rs`, `src/worker_store.rs`._

## TL;DR

- **35 story points across 14 cards.** Not blockers for the goal-v1 MVP — these are robustness/refactor/UX hardening of the coordinator runtime.
- **Critical path = `TASK-295 → TASK-289` (8 pts serial).** The keystone registry can't land cleanly until state R/W is centralized.
- **Start now with 4 independent quick wins** (287, 286, 290, 292) — zero deps, and 287 is a real safety gap (fork-bomb guard).
- **Parallelize across FILES, not within.** 8 of 14 cards touch `worker.rs` — running them in parallel = guaranteed merge hell. One stream per file.
- **One decision blocks everything durable:** pick the single source of truth between SQLite `coordinator_runs` (coordinator.rs) and the file-based `worker_store.rs`. 285/289/295 all hinge on it.

## Parallelization plan (by file, to avoid merge conflicts)

`worker.rs` is touched by **8 cards** (286, 287, 290, 292, 293, 296, 297, 298) → run these as **one serial stream**, in the order above.

Three streams can run concurrently:
- **Stream A (worker.rs):** 287 → 286 → 290 → 292 → 296 → 298 → 293 → 297
- **Stream B (coordinator.rs):** 294 → 288 → 291 (285 joins after Stream C's 295)
- **Stream C (store/db.rs):** 295 → 289, then hand 285 to whoever owns the write path

Cross-stream sync points: **295 must merge before 285 and 289**; **296 must merge before 298/293**; **294 before 291**.

## Blockers & risks

1. **Stale agent lock (environmental, not code).** All 13 cards were stuck `agent_lock_expired` since ~16:20 UTC (a145 lost its lock). **Release the stale lock before any resume** or the next worker will 409 on `acquire_agent_lock`.
2. **Two persistence surfaces.** SQLite `coordinator_runs.phase` (coordinator.rs) vs. file-based `worker_store.rs` (meta/transcript files). **Decide the single source of truth in TASK-295 first** — 285 (txn) and 289 (registry) will conflict otherwise. This is the biggest hidden coupling.
3. **TASK-288 may be obsolete.** `Outcome` already exists; `ExitReason`/`Disposition` don't. Re-read the card before starting — it may collapse to a no-op or need re-scoping to whatever a145 half-built.
4. **TASK-294 is partly done.** `Phase` enum exists; only the validated `transition()` + `Checkpoint` variant remain. Don't rebuild the enum.
5. **CI gate:** build/test with `--no-default-features --locked` (avoids the heavy `local` llama.cpp feature OOM in worktrees). Every card must pass this before PR.

## Suggested first move

Start **TASK-287** (fork-bomb guard) and **TASK-295** (repo module) in parallel — 287 is the highest-value independent safety fix, 295 is the critical-path unblocker for the two HIGH-priority keystone cards (285, 289).
