# S5.2 SPIKE — reedline parity for Ctrl-O / completer / sqlite history / Ctrl-C-D

**Status:** decided · **Date:** 2026-06-19 · **Card:** TASK-131 · **Sprint:** aish-next S5

This is a timeboxed go/no-go. The output is a decision plus a parity-gap list,
not code. It gates whether S5.4 (highlighter integration) and S5.5 (preserve
Ctrl-O / completer / history under the abstraction) target rustyline or
reedline behind the `LineEditor` trait shipped in S5.1 (TASK-130).

## Question

S5.1 put the concrete line editor behind the `LineEditor` trait
(`src/editor.rs`), so swapping rustyline for reedline is "a one-line type change
at the construction site in `repl::run`". Should we take that swap?

reedline (nushell's line editor) is the obvious candidate — fish-style history
autosuggestions, a first-class sqlite history backend, a cleaner menu model.
But aish leans on four rustyline-specific behaviours today. Can reedline
preserve all four at parity, and is the move worth it **now**?

The four load-bearing features (all in `src/repl.rs` + `src/editor.rs`):

1. **Ctrl-O toggle** — a key handler that bails out of the line editor so the
   REPL can flip raw-tool-output, print a status line, and retroactively reveal
   the last turn's raw results (`CtrlOToggle` → `Cmd::Interrupt` + `raw_toggle`
   flag, drained by `read_line` into `ReadOutcome::CtrlO`).
2. **Completer** — command-name completion (PATH scan + builtins + aliases),
   `git`/`cargo`/`docker`/`kubectl` subcommand+flag tables, path completion, and
   the `:`-command palette completion — all list-style (whole menu on first TAB).
3. **"sqlite history"** — today history is **file**-backed
   (`DefaultHistory` → `~/.aish_history`); the spike line item asks whether a
   move buys us a searchable, metadata-rich sqlite history.
4. **Ctrl-C / Ctrl-D** — Ctrl-C clears the line and loops; Ctrl-D on an empty
   line exits. (rustyline `ReadlineError::Interrupted` / `Eof`.)

Two more surfaces ride on rustyline and must not regress, because they ARE the
AI-native UX this sprint ships:

5. **Highlighter** — live route-preview coloring of the whole input line
   (green=direct, cyan=model, dim=ambiguous; S5.3/TASK-132).
6. **Hinter** — the live, multi-line `:`-command palette rendered *below* the
   prompt that filters in place as you type (`PaletteHint` / `palette_hint`).

## Verdict

**NO-GO for now. Stay on rustyline behind the `LineEditor` trait.** Point S5.4
and S5.5 at the rustyline impl. Revisit reedline only when a concrete need
appears (searchable history UI, fish-style autosuggestions) that rustyline
can't serve — at which point the S5.1 abstraction makes the swap a contained,
reversible spike, not a rewrite.

Three reasons, in order of weight:

1. **The `:`-palette Hinter has no clean reedline analog.** rustyline's `Hinter`
   lets us paint an arbitrary multi-line block below the prompt and redraw it in
   place every keystroke — that's exactly how the live `:`-command menu filters
   without re-printing the prompt or stacking menus. reedline's `Hinter` is a
   *single-line inline ghost-text* suggestion (history autosuggest); it cannot
   render a multi-row menu. We'd have to rebuild the palette as an
   always-open reedline `Menu`, but reedline menus open on a keybinding and own
   TAB/arrow semantics — they don't model "a hint that appears the instant you
   type `:` and disappears at the first space." This is the single biggest gap
   and it's load-bearing for the marquee UX.

2. **rustyline already delivers the AI UX.** As the card itself notes, reedline
   is *optional* — rustyline's `Highlighter` (route preview, S5.3) and `Hinter`
   (palette) cover the sprint goal. The Highlighter port to reedline is clean
   (whole-buffer `StyledText`), but it buys nothing over what we already have.

3. **The migration cost is real and the payoff is speculative.** Every one of
   the six surfaces needs a reedline re-implementation (table below). The only
   feature reedline gives us that rustyline doesn't — sqlite history — is
   **already partially solved**: aish records every input/output into its own
   rusqlite store (`src/db.rs`, `session.db.record(...)`), so a searchable
   history is a query away without changing the line editor at all. The
   up-arrow recall ring (file-backed) is fine as-is.

## Parity-gap list

| # | Feature | rustyline (today) | reedline equivalent | Parity? |
|---|---------|-------------------|---------------------|---------|
| 1 | Ctrl-O toggle | `bind_sequence` → `ConditionalEventHandler` returns `Cmd::Interrupt`; flag drained into `ReadOutcome::CtrlO` | `ReedlineEvent::ExecuteHostCommand("\x0f")` makes `read_line` return `Signal::Success(cmd)`; host special-cases the sentinel | ⚠️ Achievable, different shape — toggle becomes a magic host-command string instead of a typed outcome |
| 2 | Completer (cmd/path/subcommand/`:`palette) | `Completer` → `(start, Vec<Pair>)`, `CompletionType::List`, `show_all_if_ambiguous` | `Completer` → `Vec<Suggestion>` + a `ColumnarMenu`/`ListMenu` bound to TAB | ✅ Direct, full parity (Suggestion carries description for the `:`menu) |
| 3 | "sqlite history" | `DefaultHistory` → `~/.aish_history` file; **plus** aish's own rusqlite record of every input/output in `db.rs` | `SqliteBackedHistory` (feature `sqlite`) — session id, timestamps, cwd, exit, full-text search | ✅ reedline wins here, **but** aish already has the sqlite data in `db.rs`; no editor swap needed to query it |
| 4 | Ctrl-C / Ctrl-D | `ReadlineError::Interrupted` / `Eof` | `Signal::CtrlC` / `Signal::CtrlD` | ✅ Direct parity |
| 5 | Highlighter (route preview, S5.3) | `Highlighter::highlight` → `Cow<str>` over the whole line | `Highlighter::highlight` → `StyledText` over the whole buffer | ✅ Clean port, no behaviour change |
| 6 | Hinter (live multi-line `:`palette) | `Hinter` paints an **arbitrary multi-line block below the prompt**, redrawn in place each keystroke (`PaletteHint`) | `Hinter` is **single-line inline ghost text** only; menus exist but open on a keybinding and own TAB/arrows | ❌ **No clean equivalent** — would require a custom always-open menu; the dealbreaker |
| — | Above-prompt printer (bg results) | `create_external_printer()` → `ExternalPrinter`, redraws prompt after print | `ExternalPrinter` (feature `external_printer`), channel-fed, painted when idle | ⚠️ Achievable, different integration (channel `Sender` vs. a `print()` handle) |
| — | Esc clears line | `bind_sequence(Esc, Cmd::Kill(WholeBuffer))` | `Keybindings` → `EditCommand::Clear` | ✅ Direct parity |

Legend: ✅ full parity · ⚠️ achievable with rework / different shape · ❌ gap.

## Why this is the cheap decision

S5.1 was the expensive part — and it's done. With the `LineEditor` trait in
place, "stay on rustyline" costs nothing and keeps every option open:

- S5.4 (highlighter) and S5.5 (Ctrl-O / completer / history) implement against
  the **rustyline** impl that already exists; no porting tax.
- If reedline ever earns its place (a real autosuggest/history-search feature
  request), it's a self-contained `ReedlineEditor: LineEditor` added next to
  `RustylineEditor` — exactly the swap the trait was built for — and this
  parity table is the pre-written gap checklist for that spike.

## Risks / things that would flip this to GO

- **A product requirement for fish-style history autosuggestions** (inline
  ghost text from history as you type). rustyline's `Hinter` is already consumed
  by the `:`-palette, so two different hint behaviours would collide; reedline's
  autosuggest is first-class. If this lands on the roadmap, re-open the spike.
- **A searchable-history UX** (Ctrl-R fuzzy over rich metadata). Mitigated today
  by `db.rs` already holding the data — build the search over rusqlite directly
  before reaching for reedline.
- **rustyline going unmaintained.** Not the case at v18; revisit if it stalls.

## One-line summary

Stay on rustyline behind the S5.1 `LineEditor` trait: it already delivers the
route-preview Highlighter and the multi-line `:`-palette Hinter (which reedline
*cannot* render cleanly), and aish's own `db.rs` already holds the sqlite
history reedline would have bought us — so the swap is all cost and no payoff
right now. The trait keeps reedline a one-impl spike away if a concrete
autosuggest/history-search need ever appears.
